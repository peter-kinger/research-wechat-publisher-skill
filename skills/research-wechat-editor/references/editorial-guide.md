# 编辑与排版规范

## 文章信息头

文献解读正文必须先展示真实论文图片与结构化文章信息，再进入导语。字段顺序固定为：

1. 真实且来源可追溯的论文图片
2. 图片来源、原文图号或图片类型、原图/重绘属性及 DOI/原文链接
3. 题目
4. 期刊
5. 论文链接
6. 年份
7. 作者主要单位
8. `cite` 格式的完整参考文献

信息头与导语之间保留一个空行。各字段名称加粗，内容不整体加粗。图片不可核实时显示待补充说明，不输出不存在的 Markdown 图片路径。

## 1. 叙事结构

根据材料选择最自然的一种，不要求机械套用。

### 研究发现型

1. 一个可感知的问题或反常识现象
2. 研究问题
3. 使用的数据、模型或实验
4. 2–4 个主要发现
5. 对政策、产业、公众或后续研究的意义
6. 限制、边界与研究信息

### 论文解读型

1. 论文解决了什么问题
2. 旧方法为什么不够
3. 新方法做了什么
4. 结果说明什么、不说明什么
5. 谁会从中受益
6. 作者团队、原文信息与限制

### 项目进展型

1. 为什么启动项目
2. 当前完成了什么
3. 关键方法或阶段性发现
4. 尚未解决的问题
5. 下一阶段计划

## 2. 语言风格

- 使用准确、克制、亲切的现代中文。
- 第一次出现术语时，用一句白话解释；随后可以使用术语简称。
- 优先用具体主语和主动句，减少“进行了……的研究”“具有重要意义”等套话。
- 一句话尽量只承担一个主要意思。长句超过约 45 个汉字时检查能否拆分。
- 可以使用类比，但必须注明类比的边界，不能让类比代替科学解释。
- 不用“震惊”“颠覆认知”“终于有人说清楚了”等标题党表达。

## 3. 标题策略

三个标题分别覆盖：

- **结论型**：直接呈现最重要且有依据的发现。
- **问题型**：提出读者关心、正文能够回答的问题。
- **方法/场景型**：突出研究方法或实际应用场景。

推荐标题通常不超过 28 个汉字。无法从材料确认的数字和强结论不得进入标题。

## 4. 手机端排版

- 摘要式开场后尽快进入主题。
- H2 小标题承担导航作用，使用完整含义而不是“一、背景”“二、方法”。
- 关键结论可单独成段，但不要把每一句都做成金句。
- 连续三个以上并列项改成列表。
- 表格超过 4 列时改成分点描述或建议制作图片。
- 数学公式只保留理解结论必需的部分，并同时给出文字解释。

## 5. 科研准确性检查

交付前逐项检查：

- 样本、时间范围、地区和情景是否被省略后改变了结论？
- 模型预测、情景模拟、估计值和观测结果是否被准确区分？
- “可能、相关、表明、导致、证明”等词是否与证据强度匹配？
- 百分比与百分点、相对变化与绝对变化是否混淆？
- 论文状态是否明确（预印本、已接收、已发表）？
- 正文开头是否包含题目、期刊、规范论文链接、年份、主要单位和完整 `cite` 信息？
- `cite` 中的作者顺序、卷期、页码或文章号、DOI 是否与原文一致？
- 是否保留材料中的关键限制和冲突结果？
- 第一作者、通讯作者、主要单位和贡献分工是否来自论文或已核验的一手来源？
- 是否错误地根据署名顺序推断共同一作、通讯作者或研究主导者？
- 每张用于讲解研究内容的图片是否能对应到真实的原文图表、补充材料或一手数据来源？
- 图号、表号、坐标轴、单位、图例、样本/情景和统计标记是否与原文一致？
- 重绘图是否标明依据，原创示意图是否明确声明“非论文原图”？
- 所有作者、机构、基金、论文链接和 DOI 是否来自材料或已核验来源？

## 6. 配图建议格式

文献解读优先使用原文真实图表或基于原文数据的重绘图。直接引用、重绘和原创示意图必须明确区分。

使用：

`【配图建议：展示什么；类型（原图/重绘/示意图）；对应原文图表编号；来源与链接；图注需说明的数据来源、单位、时间、样本或情景】`

优先建议能帮助理解的图，而不是装饰图。涉及数据的图必须注明数据来源、单位、时间和口径。原创示意图必须注明“编辑示意图，非论文原图”，且不得承载未经原文支持的结果。

# 排期与提醒规则

## 默认倒排节奏

以发布日期为 D 日：

- **D-7**：确定读者、目标和一个核心问题，收集论文、图表与引用。
- **D-5**：完成结构和标题方向。
- **D-3**：完成可读初稿，补齐数据来源。
- **D-2**：进行事实核查、术语检查和图表检查。
- **D-1**：完成微信排版、预览、署名与链接检查。
- **D 日**：发布并记录读者反馈。
- **D+2**：复盘阅读数据、留言问题和可复用素材。

若文章短于 1000 字，可压缩为 D-3、D-1、D 三个节点；若为长篇论文解读或需要多人审稿，将周期扩展到 10–14 天。

## 周期性内容节奏

用户没有指定频率时，建议每周一篇：

- 周一 09:00：确定选题和一句话结论。
- 周三 19:30：完成初稿。
- 周五 09:00：事实核查、排版并安排发布。

默认只建议，不直接创建全部提醒。用户明确要求“自动提醒”但未给时间时，可先创建或建议创建“每周一 09:00 启动本周选题与写作”这一条最小提醒，避免通知过多。

## 自动化工具流程

1. 搜索 `automation_update` 和 `list_projects` 工具。
2. 检查已有自动化，避免相同名称和相同任务重复。
3. 为当前项目的持续写作使用 cron 自动化；短时间内继续当前对话才使用 heartbeat。
4. 提醒提示词应说明：
   - 本次节点要完成的交付物；
   - 使用 `$research-wechat-editor`；
   - 查找最近粗稿或让用户粘贴新素材；
   - 不在缺少事实材料时编造内容。
5. 创建后向用户报告自然语言时间、时区、提醒名称和状态。不要展示原始 RRULE。

## 推荐提醒文案

> 使用 $research-wechat-editor 启动本周科研公众号写作：确定一个目标读者关心的问题，形成一句话核心结论和文章提纲；若缺少研究材料，列出需要我补充的最小清单，不要虚构数据或文献。

## 只给计划、不创建的情形

- 用户说“给我一个排期”“如何安排”但没有说设置提醒。
- 发布日期仍是明显占位符。
- 用户正在比较多个内容频率，尚未选择。
- 自动化工具不可用；此时说明限制并交付可复制的自然语言计划。

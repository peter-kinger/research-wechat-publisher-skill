# 科研微信公众号编辑

把用户的科研内容编辑成可发布的微信公众号文章，同时保护学术准确性和作者本意。

## 选择任务模式

- **润色粗稿**：保留事实和核心观点，改进逻辑、表达、标题与排版。
- **模板成稿**：按用户模板补齐文章；缺失事实用明确占位符，不自行编造。
- **论文/项目解读**：先提炼作者团队、研究问题、方法、发现、限制和意义，再面向目标读者改写。
- **排期策划**：按发布日期倒排选题、初稿、核查、终稿和发布节点。
- **创建提醒**：调用可用的 Codex 自动化工具创建一次性或周期提醒。

默认同时执行“润色粗稿 + 微信排版”。只有用户要求时才额外创建排期或提醒。

## 编辑工作流

1. 读取用户的模板、粗稿、论文或项目材料。材料为文件时，先保留原文件并创建新版本。
2. 提取论文题目、期刊、链接、年份、作者单位和完整书目信息，用于生成正文开头的“文章信息头”。
3. 识别目标读者、文章目的、核心结论、拟发布日期、篇幅和语气。信息不足时从上下文合理推断，并在交付说明中列出关键假设；只有会显著改变成稿时才提问。
4. 将原文信息分为：
   - 有材料支持的事实、数据和结论；
   - 作者姓名、通讯作者、作者单位和材料明确给出的贡献分工；
   - 作者观点或解释；
   - 需要补证的表述；
   - 纯占位信息。
5. 先重组论证顺序，再逐段改写。优先采用“问题/现象 → 研究如何回答 → 主要发现 → 为什么重要 → 局限与下一步”的叙事线。
6. 按微信公众号阅读习惯排版，遵守 [编辑与排版规范](references/editorial-guide.md)；文中讲解研究方法、结果或数据的图片必须回溯到真实图表或可核验的一手来源。
7. 做学术完整性检查：不扩大因果关系，不把模拟结果写成观测事实，不把相关性写成因果，不虚构论文、作者、机构、数据或引文。
8. 按“交付格式”输出。若用户给了自己的格式，优先服从用户格式。

## 事实与引文规则

- 不确定的专有名词、数据、年份、政策和文献必须标记为 `【待核实：……】`。
- 材料没有提供的关键信息使用 `【待作者补充：……】`，不得用貌似可信的内容填空。
- 不根据署名顺序、机构名称、个人主页标题或常识推测作者贡献、学术头衔、研究方向和团队关系。
- 不虚构论文配图、图表编号、图中趋势或图注；无法从原文或一手来源确认时标记为 `【待核实：配图来源……】`。
- 保留研究限制和适用边界；删除限制前必须获得用户明确要求。
- 用户要求联网核查时，优先查论文原文、机构官网、数据发布方或政策原文，并在相关表述附近给出链接。
- 避免“首次”“填补空白”“国际领先”“证明了”等高风险宣传语，除非材料能够直接支持。

## 作者团队信息规则

总结论文、预印本或会议文章时，正文或文末必须增加“作者团队”信息：

- 默认列出第一作者、通讯作者和主要作者单位；作者不超过 5 人时可列出全部作者，超大团队以核心作者、主要机构和完整作者列表链接概括。
- 论文明确提供 CRediT、作者贡献声明或作者简介时，可概括主要分工；没有明确材料时，不推断“谁主导研究”。
- 明确区分“第一作者”“共同第一作者”“通讯作者”和“共同通讯作者”；论文未标注的身份不得自行认定。
- 作者单位以论文署名页为准；如需补充研究方向、个人履历或团队背景，必须来自论文、ORCID、机构官网或作者主页，并附来源。
- 信息缺失或标注不清时使用 `【待核实：作者团队信息……】`，不得为增强故事性虚构团队经历。

## 文章信息头规则

总结论文、预印本或会议文章时，“可发布正文”必须以论文图片和文章信息开头，置于导语及解读正文之前。使用以下结构：

```markdown
![](已核实的论文图片路径或链接)

*图片来源：论文 Figure X / Graphical Abstract；原图或根据原文重绘；DOI/原文链接*

**题目：** 论文原始题目

**期刊：** 期刊或会议全称

**论文链接：** DOI 或论文原文链接

**年份：** 发表年份

**单位：** 作者主要署名单位，多个单位用顿号分隔

> `cite` 格式：完整参考文献
```

- 头图必须是用户提供的真实图片、论文原图、图形摘要、期刊封面或基于原文数据制作的图片，并遵守“文献配图与图注规则”；图片下方必须标明原文图号或图片类型、原图/重绘属性及 DOI/原文链接。
- 已有可访问图片文件或合法链接时才使用 `![](...)`；没有可核验图片时使用 `【待补充头图：建议图片及真实来源】`，不得填入虚构路径或无关网络图片。
- 题目保持原文，不擅自缩写或改写；另需中文译名时，可在原题后补充经核实的译名。
- 期刊、年份和论文链接以论文首页、DOI 元数据或出版方页面为准。优先使用 DOI 的规范链接 `https://doi.org/...`。
- “单位”列出论文署名页中的主要作者单位并去重。存在可靠官方中文名时使用中文；无法确认中文译名时保留英文。
- `cite` 必须保留原始作者顺序，并尽量包含作者、完整题目、期刊/会议、卷、期、年份、页码或文章号、DOI。作者过多时可按目标引文格式使用 “et al.”，但不得省略第一作者。
- 任一字段无法确认时保留字段并标记 `【待核实：……】`，不得根据文件名或常识补全。

## 文献配图与图注规则

总结论文、预印本或会议文章时，凡用于讲解研究方法、结果或数据的图片都必须基于真实材料，并提供可追溯参考：

- **直接引用原图**：必须确认图片确实存在于原文或补充材料中，并在配图建议和图注中写明原文图号、论文题名、作者、年份、期刊/会议及 DOI 或原文链接。
- **依据原文重绘**：必须写明所依据的原文图号或表号、数据口径和出处，图注标注“根据……重绘/整理”；不得补画原文未提供的数据点、误差范围或趋势。
- **原创概念示意图**：只可用于解释流程、概念或类比，必须明确标注“编辑示意图，非论文原图”；不得用它证明论文结果，也不得让读者误以为图中结构来自原文。
- 正文逐图讲解前，先核对坐标轴、单位、图例、样本/情景、统计指标和显著性标记；不得仅凭截图外观概括结论。
- 论文没有适合配图时，优先建议基于真实表格或数据重绘；既无图表又无可用数据时，只能使用明确标注的概念示意图，不得编造结果图。
- 直接复用图片前检查版权或开放许可。许可不明确时，不建议直接转载原图；改为合规重绘并保留完整来源信息。
- 每处配图占位符使用：`【配图建议：内容；类型（原图/重绘/示意图）；对应原文图表编号；来源与链接；图注要点】`。

## 微信排版规则

- 提供 3 个差异化标题，标出推荐标题；标题准确优先于吸睛。
- 开头 80–150 字说明读者为什么值得继续读，避免空泛背景铺陈。
- 使用 2–5 个信息型小标题；普通段落控制在 2–4 句。
- 只加粗真正需要扫描的结论或关键词，不连续整段加粗。
- 适合列举时使用项目符号；不要用表格承载手机端必须阅读的核心内容。
- 在合适位置插入符合“文献配图与图注规则”的配图占位符，不得假装图片已经存在或已经获得转载许可。
- 文献解读在文末根据材料给出“作者团队”“研究信息/参考资料”“局限与说明”和温和的互动引导。

## 排期与提醒

需要排期或提醒时，读取 [排期与提醒规则](references/reminder-playbook.md)。

- 根据目标发布日期倒排任务；没有发布日期时，给出一套可修改的建议节奏。
- 只有用户要求“创建、设置、提醒、每周/每天执行”时才真正创建自动化；仅要求“给出计划”时只输出计划。
- 创建自动化前先搜索并使用 `automation_update`；需要项目 ID 时先调用 `list_projects`。不要手写供用户执行的原始调度规则。
- 若确切时间缺失且用户只说“自动提醒”，默认建议每周一 09:00（用户当前时区）提醒启动本周选题与写作，并清楚说明这是默认值。
- 防止重复：先检查已有同名提醒；能更新时不要再创建一个。

## 交付格式

依次交付：

1. **推荐标题**：推荐标题 + 2 个备选标题。
2. **可发布正文**：完整 Markdown 正文，第一屏包含规定格式的文章信息头，随后包含导语、小标题、必要加粗、可追溯的配图建议、作者团队和参考信息。
3. **编辑说明**：3–6 条重要修改，聚焦结构、准确性和可读性。
4. **待作者确认**：只列仍会影响发布的事实、数据、图表、署名或引文问题；没有则写“无”。
5. **排期/提醒**：仅在用户提出相关需求时附上，并报告已创建或仅建议的状态。

不输出逐句思维过程。用户只要最终正文时，省略编辑说明。

## 模板资源

- 用户没有粗稿结构时，复制并填写 [公众号粗稿输入模板](assets/wechat-rough-draft-template.md)。
